# Выкладка API Meribel: /sadovskiy-mobile/

Состояние: конфигурация подготовлена локально; на хосте ещё не применена. Текущие SSH/HTTPS-проверки хоста из рабочей среды дают таймаут. VPN владельца остаётся включённым. Новый URL сам по себе не исправляет SSH-доступ: для публикации потребуется доступ оператора или помощь администратора.

Целевой адрес: **https://tribe-i.ru/sadovskiy-mobile/**. Это маршрут существующего домена. Новый поддомен и изменение DNS не нужны. Базовый адрес мобильного API: `https://tribe-i.ru/sadovskiy-mobile`.

## Граница изоляции

- Отдельный непривилегированный пользователь ОС `sadovskiy-mobile`, без sudo, Docker-группы и групп других приложений. Его HOME: `/var/lib/sadovskiy-mobile`, режим 0700.
- Код выпуска: `/srv/sadovskiy-mobile/releases/<commit>`, ссылка `current`. Код принадлежит оператору выкладки/администратору и доступен сервису только для чтения. Сервис не должен менять свой код.
- SQLite: `/var/lib/sadovskiy-mobile/team.sqlite`, режим 0600; каталог данных и журналы — 0700. DB/WAL/SHM, резервные копии, шаблон и файлы паролей не попадают в Git, web-root или каталог раздачи.
- Отдельный PM2 daemon от нового пользователя, отдельный PM2_HOME в его HOME, процесс `sadovskiy-mobile-api`. Не добавлять процесс в PM2 старых приложений.
- API слушает только `127.0.0.1`. Кандидат внутреннего порта — 21003; администратор обязан подтвердить, что он свободен и назначен этому сервису. При выборе другого порта синхронно меняются FEATUREFLOW_PORT и nginx upstream.
- Снаружи используется существующий HTTPS 443. Внутренний порт не открывается в firewall/NAT и не слушает 0.0.0.0. Loopback сам по себе не отделяет API от других локальных процессов, поэтому авторизация обязательна на каждом маршруте с данными.
- Python ограничивает обработку восемью потоками и чтение сокета десятью секундами. При перегрузке — 503 с Retry-After; запросы не создают неограниченное число потоков.
- Черновик systemd drop-in ограничивает НОВЫЙ PM2 сервис: 512 МиБ, один CPU, 128 задач, запрет повышения привилегий, приватный /tmp, закрытые домашние каталоги и запись только в собственный каталог данных. Администратор должен проверить совместимость настроек с PM2 на хосте. PM2 max_memory_restart — дополнительный механизм перезапуска, а не строгая граница памяти.
- Общий nginx получает только location этого пути. Старые приложения, их каталоги, процессы и правила доступа не меняются. Это разделение пользователей/данных/ресурсов в общей ОС, не отдельная виртуальная машина.

## Что применяет владелец хоста

До любых изменений прочитать действующие AGENTS.md, COMMUNICATION.md, NOTES.md и адресованные оператору ответы ops/replies; сверить фактический способ публикации. Текущие шаблоны не дают оператору разрешения на sudo или правки общего nginx.

1. Создать отдельную сервисную учётку и перечисленные каталоги с правами. Выдать оператору согласованный способ загрузки кода и приватной БД, не общий root-доступ.
2. Подтвердить внутренний порт; проверить Python 3.12+ и PM2. Запустить сервис через `deploy/ecosystem.config.cjs` от его пользователя, выполнить `pm2 save`. Автозапуск и drop-in `deploy/pm2-service-hardening.conf` настраивает администратор только для нового PM2 unit.
3. Согласованно добавить `deploy/nginx-http.conf` в http-контекст; установить `deploy/nginx-proxy.conf` как `/etc/nginx/snippets/sadovskiy-mobile-proxy.conf`; добавить `deploy/nginx-locations.conf` в действующий HTTPS server для tribe-i.ru. Не создавать второй server с тем же server_name и не заменять общий конфиг целиком.
4. Проверить `nginx -t`, затем применить штатную перезагрузку. Существующий TLS-сертификат домена остаётся в управлении администратора.

Шаблоны nginx подготовлены по документации, но **nginx -t на целевом сервере ещё не выполнен**. Они не должны считаться уже установленной инфраструктурой. Ограничения входа nginx настроены по внешнему IP. Python намеренно не доверяет X-Forwarded-For: за proxy его дополнительный IP-бюджет общий, а лимит на имя пользователя остаётся отдельным.

## Перенос приватных данных

Подготовленная оператором SQLite-база с учётками и шаблоном переносится только по защищённому каналу в приватный каталог сервиса. Перед переносом сделать согласованную копию через SQLite backup API; не копировать работающую БД отдельно от WAL. Текстовый список паролей не нужен серверу: переносить credentials.json и личные карточки на хост не требуется. Файлы паролей остаются локально у владельца. Нужна отдельная приватная политика резервных копий БД; их нельзя складывать в web-root.

## Включение рабочего входа в Android

Сначала проверить HTTPS health и отказ анонимному запросу workspace, затем успешный login/workspace/logout через `deploy/smoke.py` с локальным файлом доступов. Проверить реальную запись одной согласованной фичи и чтение с другого устройства, отказ чужой команде, конфликт версии и невозможность скачать БД/конфиги по URL. Не публиковать токены в выводе проверки.

После успешных проверок скопировать `.env.example` в игнорируемый `.env.local` и перезапустить Metro. До этого адрес не активирован в приложении, чтобы не показывать рабочий вход к несуществующему API. Для готового APK изменение EXPO_PUBLIC_API_URL требует новой сборки. Запуск через Expo Go на Android уже подтверждён владельцем; командная синхронизация пока не проверена на телефонах.
